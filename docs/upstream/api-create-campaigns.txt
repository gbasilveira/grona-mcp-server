Create campaigns from your platform
This guide takes one campaign from your product to live visitors on your website, using the Public API from your backend. Follow it when you want users of your own platform to create Grona campaigns without opening the Grona Embed dashboard. The example is Acme Market’s “Free delivery bar for returning buyers” campaign; the options at the end show an A/B test across several pages.
Before you start
Section titled “Before you start”
You need a workspace secret key in the
GRONA_SECRET_KEY
environment variable of the server that calls Grona. See
Authentication
.
The Grona Embed snippet must be installed on your website. The Public API does not work with the script on the Website pages. See
Install the Grona Embed snippet
.
Your page must set the page variable the campaign targets. The example uses
window.audience_id
. See
Target by page variable
.

Open the editor links.
Each variation has an

The user makes their changes in the editor and saves them. A general campaign has one link. An A/B test has two, one for Control and one for Test, and authoring the test means opening each of them.

Preview the variation.
Open the variation’s
previewUrl
exactly as Grona returns it to see the page with the saved changes applied. Preview works while the campaign is paused, on a page that has the Grona Embed snippet. It ignores the campaign’s targeting, so it shows the variation whatever the page variable holds, and it records no page views or conversions. Keep the address as it is: preview does not follow the visitor to the next page. A preview link is not private: anyone who has the link can see the variation.

Campaign options
Section titled “Campaign options”
Beyond the four required fields, the create call can run an A/B test, run on several pages, or both. The last section explains the page variable every campaign targets.
Run an A/B test
Section titled “Run an A/B test”
Set
type
to
abTest
and Grona creates two variations, Control and Test, in that order.
trafficSplit
sets the share of eligible visitors each one gets, as whole numbers that total 100. Leave it out to split 50 and 50.
An A/B test on one page runs only when the address matches
url
exactly, query string included, so a visitor who arrives with a tracking parameter does not enter the test. A general campaign ignores the query string.
On create, the split is keyed by
Control
and
Test
, because the variation ids do not exist yet. Every response, and every update, keys it by variation id instead.
Conventions
has both shapes.
Run on several pages
Section titled “Run on several pages”
Set
pageTargeting
to
multiple
to run one campaign on a set of pages instead of one page. Four fields describe the set:
Field
Meaning
url
A sample page of the kind you want to cover. The editor opens this page. Grona stores it without its query string or fragment.
slug
One segment of the sample page’s path, spelled exactly as it appears there. What counts is its position in the path. Required.
condition
included
(the default) matches pages whose segment at that position is in
list
.
not_included
matches pages whose segment at that position is not in
list
.
list
The segments to compare against, 1 to 50 of them. Required.
Grona compares a page only when it is on the same origin as the sample
url
and its path has the same number of segments. It takes the path segment that sits at the same position as
slug
in the sample
url
, and compares it with each entry of
list
. The comparison is exact and case-sensitive. A page on another origin, or with a different number of segments, never matches, whichever
condition
you use.

audience_id
to

bakery

https://shop.example.com/Dairy/whole-milk

https://shop.example.com/bakery/bread/sourdough

https://shop.example.com/account/orders

type

condition

Target by page variable
Section titled “Target by page variable”
segmentId
and
segmentValue
are required on every create. They limit a campaign to visitors whose page sets a variable to a given value.
segmentId
is the variable’s name and
segmentValue
is the value it must hold. To reach every visitor on a page, have the page set the same value for everyone.
Your page sets the variable on
window
:
<script>
window.
audience_id
=
'returning_buyer'
;
</script>
The create request names the variable and the value, as in step 2 above.
Name:
letters, digits and
_
, not starting with a digit, at most 128 characters. Names the browser already defines, such as
name
,
location
,
status
,
top
,
parent
and
history
, are rejected.
Value:
1 to 128 letters, digits,
_
,
.
,
:
or
-
.
Match:
the variable must equal the value exactly, compared as a string.
Timing:
Grona keeps checking the variable while the visitor stays on the page, so a value set after the snippet runs still applies. Set it above the snippet so the page does not change in front of the visitor.
Target visitors by page variable
covers how to set the variable on your site, and
Page variables
is the reference for the fields.
After launch
Section titled “After launch”
Change a campaign
with
PATCH /campaigns/{campaignId}
. Send only the fields to change; the response is the whole campaign. See
Update a campaign
.
Read campaigns
with
GET /campaigns
or
GET /campaigns/{campaignId}
, using Grona’s id or your
externalId
.
Delete a campaign
with
DELETE /campaigns/{campaignId}
. Deletion is permanent and frees the
externalId
. Like a status change, it reaches visitors once your site script refreshes. If you retry an update or a delete, use Grona’s
id
, not your
externalId
; see
Conventions
.
