Errors
When a call fails, the Public API returns an HTTP status and, for most failures, an error body with a stable code. This page lists every code, the usual causes and the fix, and explains how to retry the failures that are temporary.
The error body
Section titled “The error body”
Every error the Public API returns, including
429
, uses one shape:
{
"error"
: {
"code"
:
"invalid_request"
,
"message"
:
"`url` cannot be changed; create a new campaign for a different page."
}
}
code
is stable and machine-readable. Branch on it.
message
is for people. Its wording can change, so log it but do not parse it.
Treat a
code
you do not recognise by its HTTP status. New codes can be added within v1.
A request that fails with
400
changes nothing, even when only one of its fields was at fault.
Error codes
Section titled “Error codes”
HTTP
error.code
Meaning
How to fix
400
invalid_request
The request is malformed or breaks a rule, for example a missing field, a bad format or a field that does not apply to this campaign.
Read
message
, correct the request and send it again. See the common causes below.
401
unauthorized
The secret key is missing, malformed, unknown or revoked.
Check the header and the key. See
Authentication
. Do not retry until the key changes.
403
forbidden
The request goes beyond your plan, for example the number of websites, campaigns or variations, or multi-page targeting on a plan that does not include it. Nothing was created.
Read
message
to see which limit applies. Stay within it or change your plan.
404
not_found
No campaign or variation with this id exists in the key’s workspace, or the endpoint does not exist.
Check the id, or the
externalId
you looked up. An id from another workspace also returns
404
.
409
conflict
The
externalId
is already used by another campaign in the workspace.
Use a different
externalId
, or, if you were retrying a create, fetch the existing campaign. See
Conventions
.
429
rate_limited
Too many requests.
Wait for the number of seconds in
Retry-After
, then retry.
500
internal
Something failed on Grona’s side.
Retry with backoff. If it persists, contact support.
Other
5xx
none guaranteed
A gateway in front of the API could not complete the request.
Retry with exponential backoff and jitter.
A
5xx
from a gateway may not use the JSON envelope, so decide on the status code alone.
An unknown endpoint needs a valid key to return
404
. Without a valid key it returns
401
, like every endpoint under
/api/public/v1
.

Retry temporary failures
Section titled “Retry temporary failures”
429
and every
5xx
can succeed on a later attempt. Network timeouts can too. Retry them with exponential backoff and full jitter, and when the response has a
Retry-After
header, wait at least that long. On a
429
it is a whole number of seconds. The sample below also accepts an HTTP date, in case a gateway sends one. Grona publishes no fixed rate limits, so do not hard-code a request rate; let
429
responses slow you down.
Not every request is safe to repeat blindly:
Request
Safe to retry?
GET
list and get
Yes.
PATCH
update and set status
Yes, by Grona’s campaign
id
. Sending the same fields again gives the same result. Do not retry by
externalId
: an update can change or clear it, and another campaign can then take it.
DELETE
Yes, by Grona’s campaign
id
. If the first attempt succeeded, the retry returns
404
; treat that as done. Never retry a delete by
externalId
: once the first attempt frees it, a retry can delete a new campaign that took it.
POST /campaigns
Only with an
externalId
. A retry of a create that already succeeded then returns
409
, and you fetch the campaign by its
externalId
. Without one, a retry can create a duplicate.
POST
edit-link, validate and verify-script
Yes. Each call returns a fresh answer.
POST /v1/mobile/grants
Yes. Repeat calls for the same customer return that customer’s currently valid grants. Grona does not mint a new grant for a campaign while an unexpired one exists for that customer, so a retry cannot multiply the grants a shopper can redeem.
Do not retry
400
,
401
,
403
,
404
or
409
unchanged. They fail the same way until you change the request.

Contact support
Section titled “Contact support”
If an error persists or does not match this page, email
support@grona.ai
with the time of the request in UTC, the method and path, the HTTP status and the
error.code
. Never include your secret key.
