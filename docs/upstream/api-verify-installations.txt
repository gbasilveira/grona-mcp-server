Verify installations
The verify-script endpoint loads one of your pages and reports whether your workspace’s Grona Embed snippet is on it. Call it from your backend before you set a campaign live, or in your own onboarding flow to tell a user their install is working. This page covers the request, what the check looks for, how Grona matches a URL to your website, and the cases where a working install reads
absent
.

What the check looks for
Section titled “What the check looks for”
Grona loads the page the way a first-time visitor’s browser would, and looks in
<head>
, then in
<body>
, for the
Grona Embed snippet
. A
<script>
element counts when either of these is true:
its
data-grona-embed-script
attribute holds your workspace id;
its
src
is on
personalize.grona.ai
and its path ends with
/workspaces/<your workspace id>.js
. A query string does not matter.
The workspace is the one your key belongs to, so a snippet from a different workspace reads
absent
. The script on the Website pages matches neither rule, so a page that has only that script reads
absent
too.
The check covers only the page you send, not the rest of the site. It also does not check:
that the anti-flicker line is present;
that the snippet is in
<head>
, or that it keeps its
async
attribute;
that the script loaded successfully or ran;
that your consent setup allows it to run.
Statuses
Section titled “Statuses”
The verify-script endpoint always returns a finished result:
script.status
Meaning
present
The snippet was found on the page.
absent
The snippet was not found, or Grona could not load the page.
A campaign also carries a
script
object, which reports the check of the campaign’s website. It can be in two more states, because that check runs in the background:
script.status
Meaning
checkedAt
checking
A check is running. New campaigns start here.
null
until a check has completed
present
The snippet was found.
When the check completed
absent
The snippet was not found, or Grona could not load the page.
When the check completed
unknown
No check is running and none has completed. New campaigns read
checking
, not
unknown
.
null
Before you set a campaign live, call verify-script for its page rather than relying on the campaign’s stored status.
Host matching
Section titled “Host matching”
Grona works out which website a URL belongs to in one way, for both a campaign’s
url
and the
url
you send to verify-script. It reduces the URL to its host and ignores:
the path;
a trailing slash;
a leading
www.
;
letter case.
URL
Website
https://shop.example.com/
shop.example.com
https://www.shop.example.com/dairy/whole-milk
shop.example.com
https://Shop.Example.com
shop.example.com
https://blog.example.com/
blog.example.com
, a different website
A campaign’s
domain
field holds the website’s origin, taken from its
url
, such as
https://shop.example.com
. Host matching only decides which website a URL belongs to. Grona checks the URL you send, path included, so check a page the campaign will run on. It does not widen a campaign’s targeting either: a campaign on
https://shop.example.com/
does not run on
https://www.shop.example.com/
.
Why a working install can read absent
Section titled “Why a working install can read absent”
Some setups hide the snippet from the check even though visitors get Grona.
The website script is installed instead.
The check finds only the Grona Embed snippet. See
Install the Grona Embed snippet
.
A plugin rewrites the snippet.
An optimisation plugin that moves the script to another host and removes the
data-grona-embed-script
attribute hides it from the check. Exclude the snippet from the plugin’s script handling.
A consent tool holds the script back.
The check never accepts a consent prompt. If the tool keeps the snippet off the page until the visitor accepts, or removes its
data-grona-embed-script
attribute and
src
, the check does not see it.
The script is added late.
A tag manager or a delayed-loading plugin can add the snippet after the page has loaded, too late for the check. Paste the snippet directly into
<head>
where you can.
Grona cannot load the page.
Pages behind a login, a password, a region block or bot protection read
absent
.
The wrong page.
The check covers one URL. A snippet installed only on some templates reads
absent
on the others.
Note
When the API reads
absent
and you believe the snippet is installed, open the page in a normal browser and look for the
data-grona-embed-script
attribute in the page source.
