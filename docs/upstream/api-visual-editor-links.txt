Visual editor links
An editor link opens one variation of a campaign in the Grona visual editor, in your user’s browser. Use this page when you add an “Edit” button to your product: it covers how long a link lasts, how to get a fresh one, and how to keep links from leaking.
How a link works
Section titled “How a link works”
An editor link looks like this:
https://services.grona.ai/api/public/editor/launch?token=...
The token in the query string is what lets the editor open. Anyone who holds a link that has not expired gets an editor session.
The token expires 15 minutes after it is issued.
generatedAt
and
expiresAt
in the response give the link’s window.
The link is opened in a browser. Your backend never calls it.
Treat a link as usable by whoever holds it until
expiresAt
.
The editor opens on your live page, in the user’s browser, and the
Grona Embed snippet
is what starts it. On a page without the snippet, the link opens the page but no editor starts. Check the page with
verify-script
first.
Link lifecycle
Section titled “Link lifecycle”
Create.
Creating a campaign returns an
editUrl
,
generatedAt
and
expiresAt
for every variation. An A/B test returns two links, one for Control and one for Test.
Open.
Send the link to the user’s browser while it is fresh. The user edits the variation and saves. Saving publishes the variation, so on a live campaign the saved changes reach visitors without another API call.
Expire.
15 minutes after
generatedAt
, the link stops opening the editor. Changes the user already saved are kept.
Refresh.
Request a new link with
POST /variations/edit-link
, or send the link you hold to
POST /variations/edit-link/validate
and get back a link that works.
List, get and update do not return editor links. When you need one later, request it with the variation id.
Get a new link

Check a link you hold
Section titled “Check a link you hold”
If your product keeps a link for a few minutes, for example while a user decides whether to edit, send it to the validate endpoint before you open it. Send the whole link as Grona issued it, not the token inside it:
Terminal window
curl
https://services.grona.ai/api/public/v1/variations/edit-link/validate
\
-H
"Authorization: Bearer
$GRONA_SECRET_KEY
"
\
-H
"Content-Type: application/json"
\
-d
'{"editUrl": "https://services.grona.ai/api/public/editor/launch?token=..."}'

Still valid:

Mint links when the user clicks
Section titled “Mint links when the user clicks”
The safest pattern is not to hold links at all. Give your “Edit” button a route on your own backend that checks the user, requests a fresh link and redirects the browser to it. The link then exists for a moment and is never stored.

Your route decides who may edit, so the ownership check in step 1 is not optional. Your secret key covers every campaign in your workspace, and Grona checks only that the variation is in that workspace. It cannot tell your users apart. Never send Grona a variation id taken from a request until you have matched it against the variation ids you saved, at create time, for a campaign the signed-in user owns.
The check decides who gets a link. It does not limit what the editor can reach once it is open, so give editor links only to people you trust with every campaign in the workspace. If your customers must not reach each other’s campaigns, give each one their own Grona Embed workspace.
Handle links as secrets
Section titled “Handle links as secrets”
Because the token travels in the query string, a link can end up anywhere a URL is recorded.
Open links straight away. Do not store them in your database, a cookie or local storage.
Keep them out of your logs, error reports and analytics tools. Redact the
token
parameter if a URL might be recorded.
Do not send them by email or chat, or put them in a support ticket.
Do not show them in your UI as text a user could copy and share.
Send them only to the user who asked to edit, over HTTPS.
Caution
If a link may have leaked, treat it as used. There is no call to cancel a single link early, and it stays usable until its
expiresAt
.
