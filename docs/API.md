## grona_list_campaigns

**GET `/campaigns` — List campaigns**

Returns every campaign in the workspace. v1 has no pagination: the whole list comes back
in one response, and `meta.count` is the number of campaigns returned.

The order of the list is not specified. Sort on your side if you need an order.
Variations are listed without editor links; request one with `POST /variations/edit-link`.

### MCP input

Use `{}` (no arguments).

| HTTP status | Meaning |

| 500 | Unexpected server error. `error.code` is `internal`. Retry with backoff; if it persists, contact support@grona.ai with the time of the request and the endpoint. |

## grona_create_campaign

**POST `/campaigns` — Create a campaign**

Creates a campaign and its variations in one call. A `general` campaign gets one
variation. An `abTest` campaign gets two, Control and Test, in that order.

- `name`, `url`, `segmentId` and `segmentValue` are required.
- New campaigns start `paused`. Nothing reaches visitors until you set the campaign `live`.
- The response is the only place that returns an editor link for every variation at once.
  Each link expires 15 minutes after `generatedAt`.
- Grona checks the campaign's website for the snippet after the call returns, so
  `script.status` usually starts as `checking`.
- Send `externalId` to make retries safe: a repeated create returns `409 conflict`
  instead of a second campaign.
- Plan limits apply, for example the number of websites, campaigns and variations, and
  whether multi-page targeting is included. A request over a limit returns `403 forbidden`
  and creates nothing.

`trafficSplit` is keyed by `Control` and `Test` here, because the variation ids do not
exist until this call returns. Everywhere else it is keyed by variation id.

### MCP input

Use the following JSON fields as the tool arguments.

| Field | Type | Required in parent | Meaning and constraints |
|---|---|---|---|
| `name` | string | yes | Campaign name. minLength: `1`. |
| `url` | string | yes | An `http` or `https` URL of the page the campaign runs on. With `pageTargeting` `multiple`, a sample page of the kind you want to cover; the editor opens this page, and its path must not contain `;`, quotes or backslashes. It cannot be changed later. format: `"uri"`. |
| `externalId` | string | no | Your own id for a campaign: 1 to 128 letters, digits, `_`, `.`, `:` or `-`. Unique per workspace. A UUID or a number sent as a string both work. Pattern: `^[A-Za-z0-9_.:-]{1,128}$`. |
| `segmentId` | string | yes | The name of a variable your page sets on `window`: letters, digits and `_`, not starting with a digit, at most 128 characters. Names the browser already defines, such as `name`, `location`, `status`, `top`, `parent` and `history`, are rejected. Pattern: `^[A-Za-z_][A-Za-z0-9_]{0,127}$`. |
| `segmentValue` | string | yes | The value the page variable must hold for a visitor to be eligible: 1 to 128 letters, digits, `_`, `.`, `:` or `-`. Compared as an exact string match. Pattern: `^[A-Za-z0-9_.:-]{1,128}$`. |
| `type` | string | no | `general` creates one variation. `abTest` creates two, Control and Test. Values: `general`, `abTest`. default: `"general"`. |
| `pageTargeting` | string | no | `specific` runs on the one page in `url`. An A/B test on one page needs the address to match `url` exactly, query string included. `multiple` runs on every page matched by `slug`, `condition` and `list`. Values: `specific`, `multiple`. default: `"specific"`. |
| `trafficSplit` | object | no | `abTest` only. Optional; the default is 50 and 50. Sending it for a `general` campaign returns `400`. No additional keys. |
| `trafficSplit.Control` | integer | yes |  minimum: `0`. maximum: `100`. |
| `trafficSplit.Test` | integer | yes |  minimum: `0`. maximum: `100`. |

On each page, Grona takes the path segment at the same position and compares it with each entry of `list`. The comparison is exact and case-sensitive. A visitor is eligible when the page variable `segmentId` holds `segmentValue`.
`trafficSplit` is for `abTest` campaigns only. `slug`, `condition` and `list` are for
`multiple` campaigns only. Sending any of these with the wrong kind of campaign
returns `400`.

## grona_update_campaign

**PATCH `/campaigns/{campaignId}` — Update a campaign**

Send only the fields you want to change. At least one field is required. The response
is the whole campaign after the change, including its variations. An unknown campaign
id returns `404`; update never creates a campaign.

A campaign's `type`, `url` and `pageTargeting` are fixed when it is created. Grona ignores
a `type` in the body. The call returns `400 invalid_request` and applies nothing when it:

- sends `url` or `pageTargeting`;
- sends `slug`, `condition` or `list` for a `specific` campaign;
- sends `trafficSplit` for a `general` campaign, or a split that leaves out a variation
  or does not total 100;
- sends `segmentId` or `segmentValue` for a campaign that has no page variable.

Sending one of `segmentId` and `segmentValue` keeps the other. v1 cannot remove
page-variable targeting from a campaign; create a new campaign instead.

If you retry an update, address the campaign by Grona's `id`, not by `externalId`. An
update can change or clear the `externalId`, and another campaign can then take it.

| Field | Type | Required | Meaning |
|---|---|---|---|
| `campaignId` | string | yes | Grona's campaign id or your `externalId`. A value that matches no campaign in the workspace returns `404`. |

## grona_issue_grants

**POST `/v1/mobile/grants` — Fetch grants for a shopper**

Returns the currently valid grants for one signed-in shopper. Call it from your
backend, with your Grona secret key, inside the shopper's authenticated session, then
hand the grants to the app unchanged. Take `customerId` from that session, never from a
value the app sends.

This endpoint is on https://api.grona.ai, not under the base URL above. It is available
on request and is not part of Grona Embed. Grona gives you your Grona secret key when you
get access.

Each grant is a token signed by Grona. Do not cache grants past their `exp` or share
them between shoppers. An empty list means no grant applies to this shopper right now.

Repeat calls for the same customer return that customer's currently valid grants rather
than new ones, so the call is safe to retry.

Grona has no endpoint to redeem a grant. Your order backend verifies each grant itself
at order time and makes sure each grant `jti` is used only once. If an offer must apply
once per customer rather than once per grant, your order backend enforces that too. See
[Grants and order verification](https://developer.grona.ai/mobile/backend/grants-and-orders/).

### MCP input

Use the following JSON fields as the tool arguments.

| Field | Type | Required in parent | Meaning and constraints |
|---|---|---|---|
| `customerId` | string | yes | The opaque customer id your app passes to the SDK's `identify`, taken from the shopper's authenticated session: 1 to 128 letters, digits, `.`, `_`, `:` or `-`, the same rule the SDK applies to `identify`. Never an email, a phone number or a national id. It becomes the grant's `sub` claim. Pattern: `^[A-Za-z0-9._:-]{1,128}$`. |

#### Example

```json
{
  "customerId": "cus_7Hq2Lm9x"
}
```

### Responses

| HTTP status | Meaning |
|---|---|
| 200 | The shopper's grants. Empty when none apply. |
| 400 | `customerId` is missing, or is not 1 to 128 letters, digits, `.`, `_`, `:` or `-`. `error.code` is `invalid_request`. |
| 401 | The secret key is missing, invalid or revoked. `error.code` is `unauthorized`. |
| 429 | Too many requests. Retry with exponential backoff and jitter, and wait at least as long as `Retry-After` when it is present. Branch on the status code; the body is not guaranteed to use the error envelope. |
| 500 | Unexpected server error. `error.code` is `internal`. Retry with backoff; if it persists, contact support@grona.ai with the time of the request and the endpoint. |
| 503 | Temporarily unavailable. Retry with exponential backoff and jitter, and wait at least as long as `Retry-After` when it is present. Branch on the status code; the body is not guaranteed to use the error envelope. |
